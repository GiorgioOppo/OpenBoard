# OpenBoard 0.6.1 — Early preview

OpenBoard is a self-hosted kanban and team collaboration application with a C API and a separate static web frontend. This preview brings the 0.6 feature set together with authentication hardening, updated container dependencies, seven interface languages and documentation for users and contributors.

## Included

- Boards, cards, collaboration, reviews, portfolio, sprints and internal request forms.
- English, Italian, French, Spanish, German, Simplified Chinese and Japanese interfaces.
- Session/role rechecks inside protected writes, current authorization before idempotency replay and frontend isolation across account changes.
- Bounded authentication quotas, an exact trusted-proxy address, IP-header spoofing protection and proxy request/connection limits.
- Derived PostgreSQL, MongoDB and NPM images with verified dependency replacements and retained backup/certificate tools.
- A read-only deployment preflight, a checked legacy local-proxy upgrade and isolated integration checks.
- English deployment/API/contribution/security guides, user and troubleshooting guides, community templates and dependency update proposals.

## Install and upgrade

Follow the [README](../../README.md#quick-start). The default Compose setup is local-only and stores data in separate PostgreSQL/MongoDB volumes. Version 0.6.1 retains schema 7, PostgreSQL 17 and MongoDB 8.0. Back up and verify restoration before updating an existing installation; see [deployment and migration](../DEPLOYMENT.md).

Existing local proxy configurations may need the documented `bootstrap-local.py --upgrade-proxy` step and recreation of the frontend network with the reserved static/dynamic IP ranges. Preserve volumes and plan downtime. Do not reset accounts or delete volumes to perform an upgrade.

## Validation and limitations

The candidate must have a successful complete [CI run](https://github.com/GiorgioOppo/OpenBoard/actions/workflows/ci.yml) for its exact commit. Local audit checks include default/sanitizer suites, external storage, database image tools, a real proxy chain and the five-service stack. Review the [dated remediation evidence](../SECURITY_REMEDIATION_2026-10-16.md); historical counts do not constitute a fresh scan of every final release image.

Storage serializes data operations and persists full snapshots; enterprise capacity and high availability are not established. SSO, native Trello import, external automations and antivirus scanning are not included. Visible upstream dependency findings and pending final scans remain documented. See the [roadmap and limitations](../ROADMAP.md#current-limitations).
